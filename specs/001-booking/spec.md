# Feature: <จองห้องทำงานในห้องสมุด (Booking)>
Spec ID: SPEC-BKG-001 | Source: SRS v0.3 ข้อ 3.1 (FR-BKG), ข้อ 3.3, ข้อ 3.4 | Use case: UC-01
Owner: ทีม A | Status: Draft v2 | Updated: 2569-09-20

## Goal
ผู้ใช้บริการห้องสมุดที่ยืนยันตัวตนแล้ว สามารถเลือกห้องทำงาน วันที่ และช่วงเวลาที่ต้องการใช้งาน
และได้รับหมายเลขการจองยืนยันภายใน 3 นาที โดยระบบต้องจัดสรรห้องตามจำนวนห้องที่ว่าง
และช่วงเวลาที่ว่างตาม slot ที่ UC-09 กำหนดไว้สำหรับวันเดียวกัน

## Scope
### In scope
- แสดงวัน ห้อง และช่วงเวลาที่ว่างภายใน 7 วันข้างหน้า พร้อมสถานะห้องที่ว่างอยู่ทั้งวัน
- จองห้องทำงานได้ 1 รายการต่อผู้ใช้ต่อช่วงเวลา และต้องไม่ซ้อนทับกับเวลาที่มีผู้จองหรือจองไว้ก่อนแล้ว
- ออกหมายเลขการจอง และส่งข้อความยืนยันผ่านระบบแจ้งเตือน
### Out of scope
- ยกเลิก / เลื่อนการจอง (UC-02)
- ชำระค่าปรับหรือค่าบริการ (UC-03)
- จัดการห้อง ตารางเวลา และช่วงเวลาที่เปิดให้จอง (UC-09)
- ยืนยันตัวตน (UC-13) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)

## Constraints
- CON-TECH-01 ใช้ฐานข้อมูล MySQL ตามมาตรฐานฝ่าย IT ของมหาวิทยาลัย
- DOM-PDPA-01 บันทึก audit log ทุกครั้งที่มีการเข้าถึงข้อมูลการจอง
    โดยระบุผู้เข้าถึง เวลา และรหัสผู้ใช้บริการ
    และเก็บข้อมูลไม่น้อยกว่า 1 ปี
- IF-IDP-01 ต้องได้รับผลยืนยันตัวตนจากระบบบัญชีผู้ใช้มหาวิทยาลัย
    ก่อนเข้าใช้งานระบบจองห้อง
- IF-LIB-01 ค้นข้อมูลผู้ใช้บริการจากระบบสมาชิกห้องสมุดด้วยรหัสนักศึกษา
    หรือรหัสบุคลากร และอ้างอิงภายในระบบด้วย Member ID
    โดยไม่เก็บข้อมูลส่วนตัวที่ไม่จำเป็นในตารางการจอง
- IF-NOT-01 ส่งข้อความยืนยันผ่านระบบแจ้งเตือน Email/LINE แบบ asynchronous
    โดยการจองต้องไม่รอผลการส่งข้อความ

## Requirements
- FR-BKG-01 ระบบต้องแสดงห้องและช่วงเวลาที่ว่างของแต่ละวัน
    ภายใน 7 วันข้างหน้า พร้อมสถานะห้องที่ว่างอยู่ทั้งวัน
    และคำนวณตาม slot ที่ UC-09 กำหนดไว้เป็นฐาน
- FR-BKG-02 ระบบต้องปฏิเสธการจอง เมื่อผู้ใช้มีการจองห้องที่ยังไม่สิ้นสุด
    หรือมีการจองหรือกำลังใช้งานอยู่ในช่วงเวลาซ้อนทับกับช่วงเวลาที่ต้องการจอง
    พร้อมแสดงหมายเลขการจองเดิม
- FR-BKG-03 เมื่อห้องหรือช่วงเวลาที่เลือกถูกจองเต็มระหว่างการยืนยัน
    ระบบต้องแจ้งเตือน และเสนอห้องหรือช่วงเวลาใกล้เคียง 3 ตัวเลือก
    ในวันเดียวกันเท่านั้น โดยไม่สร้างรายการจอง
    <- UC-01 exception 5a
- FR-BKG-04 เมื่อยืนยันสำเร็จ ระบบต้องบันทึกการจอง
    เปลี่ยนสถานะห้องในช่วงเวลานั้นเป็นไม่ว่าง
    ออกหมายเลขการจอง และส่งคำขอส่งข้อความยืนยัน
    <- UC-01 main flow ขั้น 6
- FR-BKG-05 หากส่งข้อความยืนยันไม่สำเร็จ ระบบต้องยังคงบันทึกการจอง
    แสดงหมายเลขการจองบนหน้าจอ และนำข้อความเข้าคิวส่งซ้ำ
    โดยพยายามส่งซ้ำภายใน 3 นาที สูงสุด 5 ครั้ง
    <- UC-01 exception 5b
- FR-BKG-06 เมื่อผู้ใช้เปลี่ยนประเภทห้องหรือจำนวนผู้ใช้งานระหว่างเลือกเวลา
    ระบบต้องคำนวณห้องและช่วงเวลาที่ว่างใหม่
    ตามเงื่อนไขที่เลือก
    <- UC-01 alternative 3a

## Quality Requirements
- NFR-PERF-01 การค้นหาห้องและช่วงเวลาว่าง:
    เวลาตอบสนอง p95 <= 2 วินาที ที่ผู้ใช้พร้อมกัน 200 คน
- NFR-SEC-01 ข้อมูลการจองต้องเข้ารหัสขณะรับส่งด้วย TLS 1.2 ขึ้นไป
- NFR-REL-02 ข้อความยืนยันที่ส่งไม่สำเร็จ
    ต้องถูกส่งซ้ำภายใน 3 นาที สูงสุด 5 ครั้ง
- NFR-USE-01 ผู้ใช้ใหม่ต้องสามารถจองห้องทำงานสำเร็จภายใน 3 นาที
    โดยผู้ทดสอบ 8 ใน 10 คนทำสำเร็จโดยไม่ต้องขอความช่วยเหลือ


## Acceptance Criteria
- AC-BKG-01 (FR-BKG-04)
    Given ยืนยันตัวตนแล้ว และห้อง Study Room A
    ช่วงเวลา 09.00-10.00 น. ยังว่าง
    When  ยืนยันการจอง
    Then  บันทึกการจองสำเร็จ แสดงหมายเลขการจอง
    และสถานะห้องช่วงเวลาดังกล่าวเปลี่ยนเป็นไม่ว่าง
- AC-BKG-02 (FR-BKG-02)
    Given ผู้ใช้มีการจองห้องที่ยังไม่สิ้นสุด
    หรือมีการจองหรือกำลังใช้งานอยู่ในช่วงเวลาซ้อนทับกับการจองใหม่
    When  ผู้ใช้พยายามจองห้องในช่วงเวลาเดียวกัน
    Then  ระบบปฏิเสธการจอง และแสดงหมายเลขการจองเดิม
- AC-BKG-03 (FR-BKG-03)
    Given ห้องที่เลือกยังว่าง และผู้ใช้อีกคนยืนยันการจองก่อน
    When  ผู้ใช้กดยืนยัน
    Then  แจ้ง “ห้องหรือช่วงเวลานี้ถูกจองแล้ว”
    แสดงห้องหรือช่วงเวลาใกล้เคียง 3 ตัวเลือก ในวันเดียวกัน
    และไม่มีรายการจองซ้อนเกิดขึ้น
- AC-BKG-04 (FR-BKG-05, NFR-REL-02)
    Given ระบบแจ้งเตือนไม่ตอบสนอง
    When  ยืนยันการจอง
    Then  การจองถูกบันทึก แสดงหมายเลขการจอง
    และมีรายการในคิวส่งซ้ำที่กำหนดส่งภายใน 3 นาที สูงสุด 5 ครั้ง
- AC-BKG-05 (NFR-PERF-01)
    Given ผู้ใช้พร้อมกัน 200 คน
    When  ค้นหาห้องและช่วงเวลาว่าง
    Then  p95 ของเวลาตอบสนอง <= 2 วินาที
- AC-BKG-06 (DOM-PDPA-01)
    Given มีการเปิดดูข้อมูลการจองห้องของผู้ใช้
    When  การเข้าถึงเสร็จสิ้น
    Then  มี audit log ที่ระบุผู้เข้าถึง เวลา และรหัสผู้ใช้บริการ

## Assumptions and Open Questions
- ASM-01 ห้องและช่วงเวลาที่เปิดให้จองกำหนดโดย UC-09
    และอ่านจากข้อมูลที่มีอยู่แล้ว
- ASM-02 “วันเดียวกัน” และช่วงเวลาการจอง
    ใช้เขตเวลา Asia/Bangkok
- ASM-03 ผู้ใช้ต้องมีสถานะสมาชิกห้องสมุดที่ยังใช้งานได้
    จึงจะสามารถจองห้องได้
- ASM-04 การจองต้องไม่ซ้อนทับกับเวลาที่มีคนจองหรือที่จองไว้ก่อนแล้ว
- ASM-05 “ห้องหรือช่วงเวลาใกล้เคียง” ให้ใช้เฉพาะวันเดียวกันเท่านั้น
- ASM-06 ห้ามจองเมื่อมีการจองแล้วหรือกำลังใช้งานอยู่
- ASM-07 การส่งข้อความยืนยันซ้ำต้องทำภายใน 3 นาที และสูงสุด 5 ครั้ง
- ASM-08 การคำนวณห้องและช่วงเวลาที่ว่างจะใช้ slot ที่ UC-09 กำหนดไว้เป็นฐาน
- ASM-09 หน้ารายการเลือกห้องควรแสดงห้องที่ว่างอยู่ทั้งวัน
